# BEQI Portfolio

แดชบอร์ดต้นแบบสำหรับ **ดัชนีคุณภาพสภาพแวดล้อมเชิงไบโอฟิลิก (Biophilic Environmental Quality Index: BEQI)**
พื้นที่ชายฝั่งเขาหลัก จังหวัดพังงา ประเทศไทย

พัฒนาตามข้อกำหนดเชิงออกแบบในบทที่ 5 ของดุษฎีนิพนธ์ ภายใต้กระบวนทัศน์การวิจัยเชิงออกแบบ
(Design Science Research; Hevner et al., 2004; Peffers et al., 2007)

## หลักการออกแบบที่บังคับใช้ในโค้ด

ทั้งสามข้อตอบข้อวิจารณ์ของ Kitchin, Lauriault และ McArdle (2015) ที่ว่าแดชบอร์ดเมือง
มักนำเสนอตัวเลขราวกับเป็นความจริงที่เป็นกลาง ทั้งที่ซ่อนการตัดสินใจเชิงระเบียบวิธีไว้เบื้องหลัง

| หลักการ | การบังคับใช้ |
|---|---|
| **เปิดเผยบริบทบังคับ** | แถบบนสุดแสดงนิยามหน่วยวิเคราะห์ รุ่นพารามิเตอร์ ความละเอียด และค่าความถูกต้องของการจำแนก ตลอดทุกหน้า |
| **ห้ามแสดงคะแนนรวมโดยลำพัง** (FR4) | การ์ดทุกใบแสดงแถบคะแนนรายตัวชี้วัดทั้งสี่คู่กับคะแนนรวมเสมอ |
| **แสดงความไม่แน่นอน** | คะแนนรวมมาพร้อมช่วงความเชื่อมั่น 95% จากการจำลองมอนติคาร์โล 5,000 รอบ |

## ความต้องการเชิงหน้าที่ที่ครอบคลุมในต้นแบบนี้

| รหัส | ความต้องการ | สถานะ |
|---|---|---|
| FR2 | คำนวณตัวชี้วัดที่ 1–3 จากข้อมูลดาวเทียม | ✅ แสดงผลที่ประมวลผลแล้ว (ประมวลผลจริงบน Google Earth Engine) |
| FR4 | แสดงค่ารายตัวชี้วัดควบคู่คะแนนรวมเสมอ | ✅ |
| FR5 | บันทึกและแสดงพารามิเตอร์กำกับผลลัพธ์ | ✅ |
| FR6 | เปรียบเทียบหลายพื้นที่ | ✅ |
| FR7 | ระบบรับรองพร้อมเงื่อนไขขั้นต่ำรายตัวชี้วัด | ✅ รวมเครื่องมือจำลองผลการรับรอง (ใช้ได้เต็มรูปแบบเฉพาะในแท็บที่มีข้อมูลครบ 4 ตัวชี้วัด) |
| FR1 | ผู้ใช้กำหนดขอบเขตพื้นที่เอง | ✅ แท็บ "วาดขอบเขตแปลงที่ดิน" ให้วาดรูปหลายเหลี่ยมของแปลงที่ดินจริงด้วยการคลิกทีละจุด (waypoint) แล้วคำนวณสดจากรูปทรงนั้นโดยตรง (client-side ผ่าน Earth Engine) |
| FR3 | แบบฟอร์มเก็บข้อมูลภาคสนาม | ❌ แท็บ "วาดขอบเขตแปลงที่ดิน" ไม่มีแบบฟอร์มกรอกข้อมูลภาคสนามในหน้านี้แล้ว — ตัวชี้วัดที่ 4 ถูกออกแบบให้มาจากระบบสำรวจภาคสนาม (backend) แยกต่างหาก ซึ่งยังไม่ได้พัฒนาในต้นแบบนี้ คะแนนที่แท็บนี้แสดงจึงเป็นค่าเฉลี่ยจาก 3 ตัวชี้วัดที่มีข้อมูลเท่านั้น ไม่ใช่ค่า BEQI ฉบับสมบูรณ์ และยังสรุปสถานะการรับรองไม่ได้ |

## เปิดใช้งานแท็บวาดขอบเขตแปลงที่ดิน (Google Earth Engine)

แท็บแรกของเว็บ **"วาดขอบเขตแปลงที่ดิน"** ให้ผู้ใช้คลิกไล่ตามขอบเขตแปลงที่ดินจริงทีละจุด (waypoint)
เพื่อสร้างรูปหลายเหลี่ยม แล้วคำนวณ BEQI แบบสดผ่าน Google Earth Engine ตรงจากเบราว์เซอร์
(client-side, ไม่ต้องมี backend) เฉพาะภายในรูปทรงที่วาดจริง โดยใช้พารามิเตอร์ชุดเดียวกับต้นแบบ
(`meta.params` / `meta.anchors` / `meta.weights` / `meta.cert_rules` ใน `data/beqi.json`)

วิธีนี้แก้ปัญหาความคลาดเคลื่อนของการวัดแบบจุดเดียว + วงกลมรัศมีคงที่ ซึ่งไม่สะท้อนรูปทรงแปลงที่ดินจริง
ที่มีทั้งแคบและกว้างต่างกัน — ตัวชี้วัดที่ 1 และ 3 คำนวณเป็นค่าเฉลี่ยภายในขอบเขตรูปหลายเหลี่ยมที่วาดโดยตรง

**ก่อนใช้งานต้องตั้งค่า 1 ครั้ง:**

1. ลงทะเบียนโปรเจกต์ Google Cloud สำหรับ Earth Engine (ไม่มีค่าใช้จ่ายสำหรับการใช้งานทั่วไป):
   https://code.earthengine.google.com/register
2. สร้าง OAuth 2.0 Client ID ชนิด **Web application** ใน Google Cloud Console →
   APIs & Services → Credentials → Create Credentials → OAuth client ID
   - ใส่ **Authorized JavaScript origins** ทั้งของเครื่องทดสอบ (เช่น `http://localhost:8000`)
     และของเว็บจริงบน GitHub Pages (เช่น `https://forestry1019.github.io`)
3. แก้ไข `assets/js/gee-config.js` ใส่ `clientId` และ `cloudProject` ที่ได้ แล้ว commit/push

เมื่อเปิดแท็บนี้ครั้งแรกจะต้องกดปุ่ม "เชื่อมต่อบัญชี Google Earth Engine" เพื่อยืนยันตัวตนด้วยบัญชี Google
ของผู้ใช้เอง (คนละบัญชีสามารถเชื่อมได้ ไม่ผูกกับเจ้าของ repo)

**วิธีวาดรูปหลายเหลี่ยม:** คลิกบนแผนที่ทีละจุดไล่ตามขอบเขตแปลงที่ดิน (อย่างน้อย 3 จุด) — คลิกจุดแรกซ้ำ
หรือกด "ปิดรูปหลายเหลี่ยม" เมื่อครบเพื่อปิดรูป ใช้ปุ่ม "ย้อนจุดล่าสุด" แก้ไขจุดที่คลิกผิดระหว่างวาด
จากนั้นกด "คำนวณ BEQI จากรูปที่วาด" (ต้องเชื่อมต่อบัญชีก่อน) หรือกด "ล้างทั้งหมด" เพื่อเริ่มวาดใหม่

**ตัวชี้วัดที่ 4 ไม่ได้กรอกในแท็บนี้:** องค์ประกอบไบโอฟิลิกเป็นข้อมูลที่ต้องมาจากระบบสำรวจภาคสนาม (backend)
แยกต่างหาก ซึ่งยังไม่ได้พัฒนาในต้นแบบนี้ คะแนนที่แท็บนี้แสดงจึงเป็นค่าเฉลี่ยจากตัวชี้วัดที่ 1–3 เท่านั้น
ไม่ใช่ค่า BEQI ฉบับสมบูรณ์ และยังสรุปสถานะการรับรองไม่ได้ (ค่า BEQI ฉบับสมบูรณ์พร้อมสถานะการรับรอง
ดูได้ที่แท็บ "ภาพรวมพอร์ตโฟลิโอ" และ "รายละเอียดรายโซน" ซึ่งใช้ข้อมูลที่มีครบ 4 ตัวชี้วัดแล้ว)

**ข้อจำกัดเชิงระเบียบวิธี** (แสดงในกล่องเตือนบนหน้าเว็บด้วย):
- ตัวชี้วัดที่ 2 ใช้ค่าเฉลี่ยขนาดกลุ่มพิกเซลสีเขียวที่เชื่อมต่อกันภายในรูปที่วาดเป็น **ตัวแทน**
  ของดัชนี Probability of Connectivity มิใช่การคำนวณกราฟ MSPA เต็มรูปแบบตามระเบียบวิธีต้นแบบ
- ตัวชี้วัดที่ 4 (องค์ประกอบไบโอฟิลิก) ไม่ได้กรอกในหน้านี้ เนื่องจากตามระเบียบวิธีเป็นข้อมูลที่ต้องสำรวจ
  ภาคสนามจริง ไม่สามารถคำนวณจากภาพดาวเทียมได้ — ออกแบบให้มาจากระบบสำรวจภาคสนาม (backend) แยกต่างหาก
  ซึ่งยังไม่ได้พัฒนาในต้นแบบนี้ คะแนนที่แสดงในแท็บนี้จึงเป็นค่าเฉลี่ยจาก 3 ตัวชี้วัดเท่านั้น
- กรอบเส้นประ 3 สีบนแผนที่คือขอบเขต 3 โซนหลักของงานวิจัยไว้อ้างอิงบริบทเท่านั้น รูปที่วาดไม่จำเป็นต้องอยู่ในกรอบเหล่านี้

## สิ่งที่ต้องพัฒนาต่อเพื่อให้เป็นระบบเชิงพาณิชย์

ต้นแบบนี้เป็น **ชั้นที่ 3 (การแสดงผล)** ของสถาปัตยกรรมสามชั้นในตารางที่ 5.9 เท่านั้น
การใช้งานจริงต้องเพิ่ม

1. **ชั้นที่ 1 การประมวลผลเชิงพื้นที่** — Google Earth Engine Python API + งานประมวลผลแบบกลุ่ม
2. **ชั้นที่ 2 บริการและตรรกะธุรกิจ** — REST API, ระบบยืนยันตัวตนหลายผู้เช่า, คิวงาน, ฐานข้อมูลเชิงพื้นที่ตามตารางที่ 5.10
3. **แบบฟอร์มภาคสนามบนอุปกรณ์เคลื่อนที่** สำหรับตัวชี้วัดที่ 4 พร้อมแนบพิกัดและภาพถ่าย

## ข้อจำกัดของข้อมูล

- ค่าดัชนีทุกค่าขึ้นกับนิยามหน่วยวิเคราะห์ (แถบชายฝั่ง 1 กม.) การอ้างอิงต้องระบุกำกับเสมอ
- ตัวชี้วัดที่ 1–3 คำนวณจากผลจำแนกชุดเดียวกัน ความคลาดเคลื่อนจึงไม่เป็นอิสระต่อกัน
- MSPA เป็นการประมาณบน Google Earth Engine มิใช่ GuidosToolbox ต้นฉบับ
- PC ใช้ direct link probability มิใช่ maximum product path ของ Conefor
- ระยะทางเป็นแบบยูคลิด มิใช่ระยะตามโครงข่ายทางเดินเท้า
- ป้ายกำกับฝึกแบบจำลองมาจาก ESA WorldCover ซึ่งเป็นข้อมูลทุติยภูมิ
- กรอบขอบเขต 3 โซนที่แสดงบนแผนที่ (`zones[].boundary` ใน `data/beqi.json`) เป็นสี่เหลี่ยมผืนผ้าตรงแนว lat/lon
  (เหนือ-ใต้ / ตะวันออก-ตก) กว้าง 1 กม. จากแนวชายฝั่ง ครอบเฉพาะช่วงหาดที่ระบุชื่อของแต่ละโซนเท่านั้น (ไม่ใช่ทั้งแนว
  ชายฝั่งของโซน) โดยอ้างอิงขอบเขตหาดจริงจาก OpenStreetMap (`natural=beach`: หาดแหลมปะการัง/หาดคึกคัก สำหรับ
  โซนเหนือ, หาดบางเนียง/หาดนางทอง สำหรับโซนกลาง, หาดเล็กใกล้ที่ทำการอุทยานฯ สำหรับโซนใต้) เป็นการประมาณเพื่อการ
  อ้างอิงบนแผนที่เท่านั้น มิใช่ขอบเขตคำนวณที่แม่นยำระดับ GIS
