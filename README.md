# BEQI Portfolio

แดชบอร์ดต้นแบบสำหรับ **ดัชนีคุณภาพสภาพแวดล้อมเชิงไบโอฟิลิก (Biophilic Environmental Quality Index: BEQI)**
พื้นที่ชายฝั่งเขาหลัก จังหวัดพังงา ประเทศไทย

พัฒนาตามข้อกำหนดเชิงออกแบบในบทที่ 5 ของดุษฎีนิพนธ์ ภายใต้กระบวนทัศน์การวิจัยเชิงออกแบบ
(Design Science Research; Hevner et al., 2004; Peffers et al., 2007)

## หลักการออกแบบที่บังคับใช้ในโค้ด

ทั้งสามข้อตอบข้อวิจารณ์ของ Kitchin, Lauriault และ McArdle (2015) ที่ว่าแดชบอร์ดเมือง
มักนำเสนอตัวเลขราวกับเป็นความจริงที่เป็นกลาง ทั้งที่ซ่อนการตัดสินใจเชิงระเบียบวิธีไว้เบื้องหลัง

| หลักการ | การบังคับใช้ |
|---|---|
| **เปิดเผยบริบทบังคับ** | แถบบนสุดแสดงนิยามหน่วยวิเคราะห์ รุ่นพารามิเตอร์ ความละเอียด และค่าความถูกต้องของการจำแนก ตลอดทุกหน้า |
| **ห้ามแสดงคะแนนรวมโดยลำพัง** (FR4) | การ์ดทุกใบแสดงแถบคะแนนรายตัวชี้วัดทั้งสี่คู่กับคะแนนรวมเสมอ |
| **แสดงความไม่แน่นอน** | คะแนนรวมมาพร้อมช่วงความเชื่อมั่น 95% จากการจำลองมอนติคาร์โล 5,000 รอบ |

| FR4 | แสดงค่ารายตัวชี้วัดควบคู่คะแนนรวมเสมอ | ✅ |
| FR5 | บันทึกและแสดงพารามิเตอร์กำกับผลลัพธ์ | ✅ |
| FR6 | เปรียบเทียบหลายพื้นที่ | ✅ |
| FR7 | ระบบรับรองพร้อมเงื่อนไขขั้นต่ำรายตัวชี้วัด | ✅ รวมเครื่องมือจำลองผลการรับรอง |
| FR1 | ผู้ใช้กำหนดขอบเขตพื้นที่เอง | 🔶 แท็บ "จุดสำรวจ" ให้เลือกได้ 1 จุดภายในขอบเขตศึกษา คำนวณสดผ่าน Earth Engine (client-side) — ยังไม่รองรับขอบเขตรูปหลายเหลี่ยมกำหนดเอง |

## เปิดใช้งานแท็บจุดสำรวจ (Google Earth Engine)

แท็บ **"จุดสำรวจ (ทดลอง)"** ให้ผู้ใช้คลิกเลือก 1 จุดภายในขอบเขตพื้นที่ศึกษา (แหลมปะการัง–หาดคึกคัก,
หาดบางเนียง–หาดนางทอง, อุทยานแห่งชาติเขาหลัก–ลำรู่) แล้วคำนวณ BEQI แบบสดผ่าน Google Earth Engine
ตรงจากเบราว์เซอร์ (client-side, ไม่ต้องมี backend) โดยใช้พารามิเตอร์ชุดเดียวกับต้นแบบ
(`meta.params` / `meta.anchors` / `meta.weights` / `meta.cert_rules` ใน `data/beqi.json`)

**ก่อนใช้งานต้องตั้งค่า 1 ครั้ง:**

1. ลงทะเบียนโปรเจกต์ Google Cloud สำหรับ Earth Engine (ไม่มีค่าใช้จ่ายสำหรับการใช้งานทั่วไป):
   https://code.earthengine.google.com/register
2. สร้าง OAuth 2.0 Client ID ชนิด **Web application** ใน Google Cloud Console →
   APIs & Services → Credentials → Create Credentials → OAuth client ID
   - ใส่ **Authorized JavaScript origins** ทั้งของเครื่องทดสอบ (เช่น `http://localhost:8000`)
     และของเว็บจริงบน GitHub Pages (เช่น `https://forestry1019.github.io`)
3. แก้ไข `assets/js/gee-config.js` ใส่ `clientId` และ `cloudProject` ที่ได้ แล้ว commit/push

เมื่อเปิดแท็บนี้ครั้งแรกจะต้องกดปุ่ม "เชื่อมต่อบัญชี Google Earth Engine" เพื่อยืนยันตัวตนด้วยบัญชี Google
ของผู้ใช้เอง (คนละบัญชีสามารถเชื่อมได้ ไม่ผูกกับเจ้าของ repo)

**ข้อจำกัดเชิงระเบียบวิธีของโหมดจุดสำรวจ** (แสดงในกล่องเตือนบนหน้าเว็บด้วย):
- ใช้วงกลมรัศมี `pc_distance_m` (ค่าเริ่มต้น 500 ม.) รอบจุดที่เลือก แทนแถบชายฝั่ง 1 กม. ที่ใช้สร้างข้อมูลต้นแบบ
  ผลจึงไม่เทียบเท่าค่าระดับโซนโดยตรง
- ตัวชี้วัดที่ 2 ใช้ขนาดกลุ่มพิกเซลสีเขียวที่เชื่อมต่อกัน ณ จุดที่เลือก (สูงสุด 256 พิกเซล) เป็น **ตัวแทน**
  ของดัชนี Probability of Connectivity มิใช่การคำนวณกราฟ MSPA เต็มรูปแบบตามระเบียบวิธีต้นแบบ
- ตัวชี้วัดที่ 4 (องค์ประกอบไบโอฟิลิก) มาจากการกรอกแบบตรวจสอบด้วยตนเองในหน้าเว็บ เนื่องจากตามระเบียบวิธี
  เป็นข้อมูลที่ต้องสำรวจภาคสนามจริง ไม่สามารถคำนวณจากภาพดาวเทียมได้

## สิ่งที่ต้องพัฒนาต่อเพื่อให้เป็นระบบเชิงพาณิชย์

ต้นแบบนี้เป็น **ชั้นที่ 3 (การแสดงผล)** ของสถาปัตยกรรมสามชั้นในตารางที่ 5.9 เท่านั้น
การใช้งานจริงต้องเพิ่ม

1. **ชั้นที่ 1 การประมวลผลเชิงพื้นที่** — Google Earth Engine Python API + งานประมวลผลแบบกลุ่ม
2. **ชั้นที่ 2 บริการและตรรกะธุรกิจ** — REST API, ระบบยืนยันตัวตนหลายผู้เช่า, คิวงาน, ฐานข้อมูลเชิงพื้นที่ตามตารางที่ 5.10
3. **แบบฟอร์มภาคสนามบนอุปกรณ์เคลื่อนที่** สำหรับตัวชี้วัดที่ 4 พร้อมแนบพิกัดและภาพถ่าย

## ข้อจำกัดของข้อมูล

- ค่าดัชนีทุกค่าขึ้นกับนิยามหน่วยวิเคราะห์ (แถบชายฝั่ง 1 กม.) การอ้างอิงต้องระบุกำกับเสมอ
- ตัวชี้วัดที่ 1–3 คำนวณจากผลจำแนกชุดเดียวกัน ความคลาดเคลื่อนจึงไม่เป็นอิสระต่อกัน
- MSPA เป็นการประมาณบน Google Earth Engine มิใช่ GuidosToolbox ต้นฉบับ
- PC ใช้ direct link probability มิใช่ maximum product path ของ Conefor
- ระยะทางเป็นแบบยูคลิด มิใช่ระยะตามโครงข่ายทางเดินเท้า
- ป้ายกำกับฝึกแบบจำลองมาจาก ESA WorldCover ซึ่งเป็นข้อมูลทุติยภูมิ
